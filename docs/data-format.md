# 数据格式（v3）

## 目录

| 路径 | 内容 |
| --- | --- |
| `$JK_HOME`（默认 `~/.jk`） | 数据根目录 |
| `.env` | 配置，见 README |
| `jk.json` | `{"format": 3}`，数据格式版本号 |
| `notebooks/<名字>.md` | 记事本，一本一个文件 |
| `archive/<名字>.md` | 归档，同名对应，格式相同 |
| `history/<时间戳>/` | 撤销快照：`notebooks/`、`archive/` 的整份拷贝 + `meta.json` |
| `backups/<时间戳>-v<旧版本>/` | 格式升级前的整份备份 |
| `state.json` | 运行状态（`ucloud_synced_on` 今天是否已同步、`ucloud_failed_at` 上次失败时间）；不属于数据格式，删掉只会多同步一次 |
| `pastes/<时间戳>/` | 输入框的粘贴内容（`1.txt`、`2.png`…），发送后删除；不属于数据格式，不迁移 |

## 记事本文件

```markdown
---
jk_format: 3
title: 作业
created: 2026-10-13
---

# 作业

- [ ] 完成作业 a <!-- jk id=2 due=2026-10-14T15:00 pri=2 created=2026-10-13T10:00 -->
- [/] 复习期中 <!-- jk id=3 due=2026-10-20 created=2026-10-13T10:05 -->
- [x] 交项目周报 <!-- jk id=1 created=2026-10-12T10:00 done=2026-10-13T09:00 -->
- 健身房周日闭馆 <!-- jk id=4 created=2026-10-13T11:00 -->
```

- `title` 是记事本名（以它为准，文件名只是它的安全版本）。
- 每行一个条目。方框：`[ ]` 待办，`[/]` 进行中，`[x]` 完成；没方框 = 笔记；`↻ ` 开头 = 周期。
- 行尾 `<!-- jk ... -->` 存元数据，Obsidian 阅读模式下不显示：

| 键 | 含义 | 必有 |
| --- | --- | --- |
| `id` | 编号（全部记事本里唯一） | 是 |
| `due` | 截止：`YYYY-MM-DD` 或 `YYYY-MM-DDTHH:MM`（只有日期 = 当天 23:59） | 否 |
| `pri` | 优先级 2=重要、3=紧急；1 省略 | 否 |
| `created` | 创建时间 | 是 |
| `done` | 完成时间 | 完成时有 |
| `every` | 周期规则（只有周期条目有） | 周期必有 |
| `src` | 外部来源编号，如 `ucloud:2104195020042915841`（`jk u` 同步来的条目有） | 否 |

### 周期条目（v2 新增）

```markdown
- ↻ 跑步 <!-- jk id=6 created=2026-10-13T10:00 every=weekly:1@08:00 -->
```

- 全部放在 `notebooks/周期.md`，这个记事本由程序管理（不能改名、合并，也不能放普通条目）。
- 没有方框、截止、优先级、完成时间；不会被归档。
- `every` 规则：

| 写法 | 含义 |
| --- | --- |
| `daily` | 每天 |
| `weekdays` | 工作日（周一到周五） |
| `weekly:1,3` | 每周一、三（1=周一 … 7=周日） |
| `monthly:15` | 每月 15 号；本月没有这天（如 31 号）就落在月底 |
| `…@HH:MM` | 加钟点，例：`weekly:2,4@16:00`；不写 = 全天 |

- 手写时 `every` 缺失或写错，这一行会当普通笔记保留，不丢内容。

## 手改规则

- 可以直接改文字、勾方框、加新行（`- [ ] xxx`），下次运行 jk 会自动补编号和时间。
- 编号重复时，后出现的那条会换新编号。
- 认不出的行（比如一段话）原样保留在文件末尾，不会丢。
- 时间格式写错的 `due` 会被忽略。

## 编号

新条目取「当前没被占用的最小编号」。归档后编号会被复用，所以归档条目在时间线里不显示编号。

## 版本历史

| 版本 | jk | 变化 | 迁移 |
| --- | --- | --- | --- |
| v1 | 0.1 – 0.3 | 初版 | — |
| v2 | 0.4 – 0.5 | 新增周期条目与 `every` 键 | 自动：先备份，再重写文件头为 `jk_format: 2`，内容不变 |
| v3 | 0.6 起 | 新增 `src` 键与「云邮」记事本 | 自动：先备份，再重写文件头为 `jk_format: 3`，内容不变 |

旧版 jk 打开新版数据会拒绝运行（它不认识新字段，保存时会丢掉 `every` / `src`）。

「云邮」（`notebooks/云邮.md`）和「周期」一样由程序管理：只放 `jk u` 同步来的条目。

## 兼容承诺

1. 新版 jk 必须能读所有旧版数据：格式变化时 `FORMAT_VERSION` +1，并提供迁移。
2. 迁移前自动整份备份到 `backups/`；迁移缺失时不动数据、直接报错。
3. 旧版 jk 遇到更新的数据会拒绝运行，不会写坏。
4. 配置改键名时，旧键名通过 `config.ALIASES` 继续生效。
5. 未知的元数据键、未知的行都保留或忽略，不报错。
